# Руководство по миграции с JSON на SQLite

## Введение

Бот Book Shelf теперь использует SQLite для хранения данных вместо JSON-файлов. Это улучшает производительность, надежность и масштабируемость приложения.

## Что изменилось

- **Прежнее хранилище**: Данные хранились в JSON-файлах (`data/books.json`, `data/users.json`)
- **Новое хранилище**: Данные теперь хранятся в базе данных SQLite (`data/database.db`)

## Преимущества

1. **Быстродействие**: SQLite значительно быстрее для операций чтения/записи
2. **Надежность**: Транзакции и восстановление после сбоев
3. **Масштабируемость**: Легче управлять большими объемами данных
4. **Совместимость**: Поддержка внешних ключей и ограничений целостности

## Миграция данных

### Автоматическая миграция

1. Убедитесь, что у вас есть резервная копия существующих JSON-файлов:
   ```bash
   cp -r data data_backup
   ```

2. Запустите скрипт миграции:
   ```bash
   python src/utils/migrate.py
   ```

3. Скрипт автоматически перенесет все данные из JSON-файлов в базу данных SQLite

### Ручная миграция

Если вы хотите вручную проверить данные перед миграцией:

1. Создайте базу данных:
   ```python
   from core.database import Database
   db = Database()
   ```

2. Мигрируйте данные:
   ```python
   db.migrate_from_json("data")
   ```

## Настройка бота

После миграции бот будет автоматически использовать базу данных. Никаких дополнительных изменений в коде не требуется.

## Проверка данных

Вы можете проверить, что данные мигрированы корректно:

```python
from core.services import BookService, UserService

# Проверка книг
book_service = BookService()
books = book_service.get_all_books()
print(f"Книг в базе: {len(books)}")

# Проверка пользователей
user_service = UserService()
users = user_service.get_all_users()
print(f"Пользователей в базе: {len(users)}")
```

## Обратная совместимость

- Старые JSON-файлы сохраняются и не удаляются автоматически
- Вы можете продолжать использовать их для анализа или резервного копирования
- Новые данные будут записываться только в базу данных

## Устранение проблем

### Проблема: База данных не создается

**Решение**: Убедитесь, что у вас есть права на запись в директорию `data/`

### Проблема: Ошибки при миграции

**Решение**: Проверьте формат JSON-файлов. Если файлы повреждены, восстановите их из резервной копии.

### Проблема: Старые данные не отображаются

**Решение**: Убедитесь, что миграция была выполнена успешно. Проверьте лог миграции.

## Технические детали

### Структура базы данных

**Таблица `users`:**
- `id` (TEXT, PRIMARY KEY)
- `telegram_id` (INTEGER, UNIQUE)
- `username` (TEXT)
- `first_name` (TEXT)
- `last_name` (TEXT)
- `created_at` (TEXT)
- `last_active` (TEXT)

**Таблица `books`:**
- `id` (TEXT, PRIMARY KEY)
- `title` (TEXT, NOT NULL)
- `author` (TEXT, NOT NULL)
- `tags` (TEXT, JSON-строка)
- `pages` (INTEGER, NOT NULL)
- `current_page` (INTEGER, NOT NULL, DEFAULT 0)
- `status` (TEXT, NOT NULL)
- `created_at` (TEXT, NOT NULL)
- `updated_at` (TEXT, NOT NULL)
- `cover_image` (TEXT)
- `notes` (TEXT)
- `reading_start_date` (TEXT)
- `reading_end_date` (TEXT)
- `user_id` (TEXT, NOT NULL, FOREIGN KEY)
