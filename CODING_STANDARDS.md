# Стандарты разработки

Документ определяет обязательные правила написания, размещения и проверки кода в проекте.

## Стиль кода

- Комментарии пишутся на русском языке.
- Все импорты размещаются в начале файла, а не внутри функций или других блоков кода.
- При импорте модулей внутри одного пакета используются относительные импорты.
- Форматирование выполняется с помощью Black и isort. Их настройки находятся в `pyproject.toml`, правила Flake8 — в `.flake8`.

## Организация кода

- Код VK-бота размещается в `src/vk_bot/`, обработчики команд — в `src/vk_bot/handlers/`.
- Бизнес-логика размещается в `src/core/` и не зависит от VK.
- Вспомогательные функции размещаются в `src/utils/`.
- Каждый обработчик команды находится в отдельном файле в `src/vk_bot/handlers/`.
- Общие клавиатуры находятся в `src/vk_bot/keyboards.py`. Клавиатуры, которые использует только одна команда, определяются в файле её обработчика.

## Обработчики команд

- Одношаговые команды наследуются от `AbstractCommandHandler`, многошаговые — от `ScenarioHandler`.
- Защита от команд во время активного чужого сценария уже реализована в шаблонном методе `AbstractCommandHandler.handle()`; в конкретных обработчиках её не дублируют.
- Только глобальные команды `/start` и `/cancel` помечаются `is_system = True`.
- В `scenario_command` указывается каноническая команда сценария, которая записывается в `state["command"]`. У одношаговых команд остаётся `None`.
- `CommandRouter` выполняет два прохода: сначала ищет обработчик по введённой команде, затем — по команде из активного состояния для шагов со свободным текстом. Конкретный обработчик реализует только свою бизнес-логику.

### Многошаговые сценарии

- Объявляются перечисление шагов `states`, начальный шаг `initial_state` и каноническая команда `scenario_command`.
- Для каждого шага объявляется метод `step_<state>(context, state_info)`. Полнота покрытия шагов проверяется при импорте модуля.
- Метод шага возвращает имя следующего состояния или `None`, если нужно остаться на текущем шаге.
- Для отправки приглашения шага добавляется `render_<state>(context, state_info)`.
- Сценарий запускается через `begin()`, переход между шагами выполняется через `goto()`.
- Завершение выполняется через `finish()`: сначала отправляется финальное сообщение, затем удаляется состояние.
- Повторный ввод собственной команды перезапускает сценарий: это payload с `command`, но без `action`, или текст, начинающийся с `/`. Обработка уже реализована в `ScenarioHandler`.
- Неизвестный шаг автоматически обрабатывается через `reset_unknown_state()`.

## Конфигурация

- Конфигурация загружается из переменных окружения; локальные значения хранятся в `.env` и загружаются через `python-dotenv`.
- Поддерживаются переменные `BOT_TOKEN`, `DATA_DIR`, `TEMP_DIR` и `DEBUG`. Их значения по умолчанию определяются в `src/utils/config.py`.
- Токены, пароли и другие секреты не включаются в исходный код и не коммитятся в репозиторий.

## Тестирование

- Тесты размещаются в `tests/` и используют pytest.
- Для новой функциональности добавляются тесты, а при исправлении ошибок — регрессионные тесты.
- Существующие тесты обновляются при изменении поведения приложения.
- Во время разработки полезно запускать `pytest -x`, чтобы остановиться на первой ошибке.
- Для проверки отдельного файла или теста используются команды:

  ```bash
  pytest tests/test_services.py
  pytest tests/test_services.py::test_filter_by_status
  ```

## Обязательная проверка изменений

После завершения изменений из корня репозитория выполняются все команды:

```bash
isort .
black .
flake8 src/
pytest
```

Изменения считаются завершёнными только после успешного выполнения всех проверок.

Для проверки покрытия используются команды:

```bash
coverage run -m pytest
coverage report
```
