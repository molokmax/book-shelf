## Context

- `main_keyboard()` (`src/vk_bot/keyboards.py`): 10 кнопок в 3 ряда. Кнопки команд текстовые без payload; единственная payload-кнопка «Отмена» (`{"command": "/cancel"}`).
- `BotContext.command` (`src/vk_bot/context.py`) сначала читает `payload["command"]`, затем текст сообщения: payload-кнопка маршрутизируется как команда независимо от надписи.
- Роутер (`command_router.py`) делает два прохода: по введённой команде, затем по команде активного состояния. Конвенция AGENTS.md: при чужом активном сценарии `handle()` возвращает `None`; эталон соблюдён в `progress.py`, `goal.py`, `settings.py`.
- Все хендлеры по завершении команды отправляют `main_keyboard()` (`export`, `goal`, `stats`, `edit` и другие): после выполнения команды из подменю пользователь автоматически видит главное меню.
- Раскладка главной клавиатуры зафиксирована тестом `test_main_keyboard_contains_progress_command` (`tests/handlers/test_progress_handler.py`).
- Аналитики использования команд нет: состав «самых востребованных» зафиксирован продуктовым решением в grilling-сессии.
- Паттерн «Назад» в `SettingsHandler` (текстовая кнопка, «Возврат в главное меню») не подходит для меню: там «Назад» закрывает сценарий с состоянием, у меню сценария нет.
- `/help` не упоминает `/details`.

## Goals / Non-Goals

**Goals:**

- Главное меню из 5 команд + «Ещё»: ежедневный цикл (прогресс, детали, список, добавление) и справка в одном тапе.
- Подменю «Ещё» с остальными 5 командами и «Назад», симметричная раскладка 2 ряда по 3.
- Stateless-навигация: открытие и закрытие подменю не пишет состояние в `user_state`.
- Возврат в главное меню после выполнения любой команды из подменю без изменений хендлеров (текущее поведение).
- Гард чужого сценария в `MoreHandler` по конвенции AGENTS.md.

**Non-Goals:**

- Унификация навигации «Назад» и сообщений возврата в остальных командах (settings, многошаговые диалоги): отложено, issue не создаётся по решению пользователя.
- Приведение гардов `edit` / `details` / `list` / `add` / `start` / `help` / `stats` / `export` к конвенции AGENTS.md: отложено, отдельная тема (нарушения обнаружены в grilling-сессии: `edit.py` и `details.py` возвращают `True` при чужом сценарии, `list.py` и `add.py` не проверяют команду стейта, одношаговые хендлеры без гарда).
- Изменение поведения или составов самих команд: переносятся только кнопки.
- Уровни меню глубже одного.
- Аналитика востребованности команд.

## Decisions

1. **Состав главного меню: `/progress`, `/details`, `/list`, `/add`, `/help` + «Ещё»**
   - Решение пользователя в grilling-сессии: ежедневный цикл трекера и справка; всё остальное реже раза в день.
   - Следствие принято осознанно: `/edit` (единственный путь сменить статус, включая «Прочитано») уходит в подменю, 2 тапа вместо 1. Смена статуса редка относительно ежедневного обновления прогресса.

2. **Раскладки: 2 ряда по 3, навигационная кнопка замыкает второй ряд**
   - Главное: ряд 1 `/progress /details /list`, ряд 2 `/add /help «Ещё»`. Подменю: ряд 1 `/edit /export /goal`, ряд 2 `/stats /settings «Назад»`.
   - Симметрия главного меню и подменю; «Ещё» и «Назад» в одинаковой позиции. Подписи короткие, VK рендерит 3 кнопки в ряд без обрезки.

3. **Stateless-навигация через payload**
   - Кнопка «Ещё»: надпись «Ещё», payload `{"command": "/more"}`. Кнопка «Назад»: payload `{"command": "/back"}`. Оба обрабатывает новый `MoreHandler` (`priority = 10`, `commands = ["/more", "/back"]`).
   - Состояние диалога не пишется: смена клавиатуры это смена вида, а не сценарий. Альтернатива state-machine по образцу settings отвергнута: состояние без данных и валидаций, плюс конфликт с гардом чужих сценариев.
   - Payload-подход консистентен с «Отмена». Побочный эффект: ручной ввод текста «ещё» команду не триггерит. Принято: навигация не команда.

4. **Экран «Ещё» и возврат**
   - `/more`: экран со списком команд и краткими описаниями (формулировки из `/help`) + `more_keyboard()`:
     ```
     Ещё

     /edit - Редактировать книгу
     /export - Экспорт списка книг в CSV
     /goal - Дневная цель чтения
     /stats - Статистика чтения
     /settings - Настройки приложения
     ```
   - `/back`: сообщение «Главное меню» + `main_keyboard()`.
   - Альтернатива «Назад» через `CancelHandler` отвергнута: «Операция отменена» вводит в заблуждение, отменять нечего; `CancelHandler` к тому же удаляет состояние, которого здесь нет.

5. **После команды из подменю: главное меню без изменений**
   - Хендлеры по завершении цепляют `main_keyboard()`: выполнив команду из подменю, пользователь автоматически возвращается в главное меню. Отдельный код не нужен.

6. **Гард чужого сценария**
   - В начале `handle()`: `return None`, если `context.is_active()` и команда стейта не входит в `["/more", "/back"]`. Нажатие «Ещё»/«Назад» при чужом активном сценарии (клавиатура могла остаться от предыдущего сообщения) вторым проходом роутера доходит до сценария и обрабатывается им как обычный текст. «Отмена» перехватывается `CancelHandler` глобально как обычно.

7. **`more_keyboard()` в `keyboards.py`**
   - Клавиатура уровня меню, пара к `main_keyboard()`, хотя потребитель один (`MoreHandler`). Альтернатива: файл хендлера по прецеденту settings. Отвергнута: клавиатура настроек специфична для сценария, подменю это инфраструктура меню, как `main_keyboard()` и `cancel_keyboard()`.

8. **`/start` и `/help`**
   - `/start`: новый текст приветствия:
     ```
     Привет! Я твой персональный трекер чтения и менеджер книг.

     Что я могу сделать:
     /add - Добавить новую книгу
     /progress - Обновить прогресс чтения
     /list - Показать список книг
     /details - Детали книги
     /help - Помощь

     Остальные команды доступны через кнопку «Ещё».

     Начни с добавления первой книги!
     ```
   - `/help`: добавляется строка `* /details - Полная информация о выбранной книге` (сейчас команда отсутствует в справке при видимой кнопке в главном меню).

## Risks / Trade-offs

- **[/edit в подменю]** Смена статуса книги теперь 2 тапа. Принято: осознанное следствие приоритета ежедневных действий.
- **[Навигация только кнопкой]** Ручной ввод «ещё» или «назад» не открывает подменю: маршрутизация по payload. Принято: меньше случайных срабатываний, консистентно с «Отмена».
- **[Клавиатура устаревает]** Сообщения без клавиатуры сохраняют предыдущую: подменю может остаться видимым до следующего сообщения бота с клавиатурой. Мягкий кейс: любая команда или «Назад» возвращает главное меню.
- **[Тест фиксирует раскладку]** Layout-тест завязан на порядок кнопок и payload навигационных кнопок: будущие перестановки потребуют правки теста. Это его назначение.

## Migration Plan

- Данные не затрагиваются: нет новых таблиц, `user_state` не используется, миграций нет.
- Существующие пользователи получают новую главную клавиатуру со следующего сообщения бота с клавиатурой, специальных действий не нужно.
- Откат: вернуть прежнюю раскладку `main_keyboard()`, удалить `MoreHandler`, `more_keyboard()` и регистрацию в `bot.py`; поведение команд не меняется.
