## Context

Пользователи получают слишком длинный список книг при запросе `/list`. Требуется добавить интерактивную фильтрацию по статусу и тегам, чтобы сократить выдачу и улучшить UX.

## Goals / Non-Goals

**Goals:**
- Позволить пользователю выбирать один из четырёх вариантов: по статусу, по тегам, все книги, отмена.
- При выборе "по статусу" показать клавиатуру со всеми возможными статусами и вывести книги с выбранным статусом.
- При выборе "по тегам" показать клавиатуру со всеми используемыми тегами и вывести книги с выбранным тегом.
- Реализовать фильтрацию на уровне сервисов (`BookService`) и репозитория (`BookRepository`).

**Non-Goals:**
- Не менять схему базы данных.
- Не добавлять новые типы сущностей или внешние зависимости.
- Не переосмысливать логику остальных команд бота.

## Decisions

- **Клавиатура**: Добавить новые кнопки в `src/bot/keyboards.py` и отдельные клавиатуры для статусов и тегов.
- **Обработчик `list`**: Расширить `src/bot/handlers/list.py` для пошагового диалога (выбор варианта → запрос статуса/тега → вывод).
- **Сервис**: Добавить методы `filter_by_status` и `filter_by_tag` в `src/core/services.py`, которые вызывают соответствующие репозиторные функции.
- **Репозиторий**: Реализовать `get_by_status` и `get_by_tag` в `src/core/repository.py` с простыми SQL‑запросами.
- **Тесты**: Добавить юнит‑тесты для новых сервисных методов и обновить интеграционные тесты обработчика.

## Risks / Trade-offs

- **Сложность UI**: Дополнительные шаги могут запутать пользователей; mitigated by добавлением кнопки «Отмена» на каждом этапе.
- **Производительность**: Фильтрация по тегам может вернуть много записей; mitigated ограничением количества выводимых книг (например, 20) и пагинацией в будущем.
- **Поддержка новых статусов/тегов**: Требует обновления клавиатур; mitigated вынесением списка статусов/тегов в конфигурацию.
