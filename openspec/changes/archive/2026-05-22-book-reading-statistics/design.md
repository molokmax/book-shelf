## Context

В проекте уже используется SQLite база данных, где хранятся модели книг и пользователей. Нужно добавить в неё таблицу/колонки для статистики чтения (количество прочитанных страниц, дата обновления) и обеспечить обновление этих данных при изменении прогресса книги.

## Goals / Non-Goals

**Goals:**
- Реализовать хранение и обновление статистики чтения в единой SQLite базе данных проекта.
- Сохранять агрегированные данные, чтобы в будущем можно было выводить количество прочитанных страниц за неделю, две недели, месяц и прогнозировать конец книги.

**Non-Goals:**
- Вывод готовой статистики в пользовательском интерфейсе (будет реализовано позже).
- Миграция данных из существующего JSON‑файла (в текущей версии статистика не используется).

## Decisions

- **Хранение:** использовать ту же SQLite базу, добавив новую таблицу `read_stats`. Колонки в таблице: `id` INTEGER PRIMARY KEY AUTOINCREMENT, `book_id` INTEGER NOT NULL, `pages_read` INTEGER NOT NULL, `read_date` TEXT NOT NULL.
- **Обновление статистики:** в сервисе `BookService` в `src/core/services.py`, в методе обновления прогресса, реализовать добавление записи в таблицу статистики.
- **Миграция схемы:** использовать простой CREATE TABLE запрос для добавления таблицы.
- **Тестирование:** добавить юнит‑тесты для нового поведения и проверить миграцию на тестовой базе.

## Risks / Trade-offs

- **Риск:** изменение схемы базы может вызвать конфликт с уже установленными версиями; mitigated by applying migration on startup with `IF NOT EXISTS` checks.

## Migration Plan

- **Шаг 1**: При старте приложения выполнить миграцию:
  ```sql
  CREATE TABLE IF NOT EXISTS read_stats (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    book_id INTEGER NOT NULL,
    pages_read INTEGER NOT NULL,
    read_date TEXT NOT NULL
  );
  ```
- **Шаг 2**: Обновить модели в `src/core/models.py`, добавив Pydantic‑модель `ReadStat` с полями `id`, `book_id`, `pages_read`, `read_date`.
- **Шаг 3**: В `src/core/database.py` добавить функцию `init_read_stats()` и вызвать её при инициализации базы.
- **Шаг 4**: В `src/core/services.py` в методе обновления прогресса книги вызвать `ReadingStatsService.add_record(book_id, pages_read, date)` для записи в `read_stats`.
- **Шаг 5**: Написать юнит‑тесты, проверяющие создание таблицы, добавление записи и корректность данных.
- **Шаг 6**: При деплое выполнить миграцию на продакшн‑базе, убедившись, что `IF NOT EXISTS` не ломает существующие данные.
