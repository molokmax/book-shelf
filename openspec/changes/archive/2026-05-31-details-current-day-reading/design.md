## Context

Текущий модуль `details` собирает статистику о прочитанных страницах, но не учитывает чтения, произведённые в текущий календарный день. Это приводит к неверному подсчёту общего количества прочитанных страниц и неточному прогнозу завершения книги.

## Goals / Non-Goals

**Goals:**
- Учёт данных о прочтенных страницах за текущий день в расчётах статистики и прогноза.
- Обновление соответствующей бизнес‑логики без изменения публичного API команды `details`.

**Non-Goals:**
- Полный рефакторинг системы подсчёта чтения; изменения ограничиваются только учётом текущего дня.

## Decisions

- Использовать существующий сервис `ReadingStatsService` (или аналогичный) и изменить методы, принимающие параметры начала и конца периода, чтобы они использовали тип `datetime` вместо `date`. Параметр `to_date` должен указывать на конец дня (23:59:59), а не на начало.
- При вызове `details` передавать текущую дату через `datetime.date.today()` и включать её в агрегатные функции.
- Не менять структуру БД; данные за текущий день уже сохраняются в таблице `reading_progress`, достаточно включить их в запрос.

## Risks / Trade-offs

- **Риск:** Возможные регрессии в расчётах для исторических данных, если текущий день уже был учтён в другом месте.
  - **Митигaция:** Написать тесты, покрывающие сценарий, когда пользователь читает в течение дня и сразу вызывает `details`.
- **Риск:** Добавление нового параметра может потребовать обновления мок‑объектов в тестах.
  - **Митигaция:** Обновить все соответствующие фикстуры и проверить покрытие.
