## ADDED Requirements

### Requirement: Сборка образа из корня репозитория

Система SHALL собирать Docker-образ бота командой `docker build` из корня репозитория. Образ SHALL базироваться на `python:3.11-slim`, использовать многоступенчатую сборку (builder + runtime), устанавливать только зависимости из `requirements-prod.txt` и запускать приложение от непривилегированного пользователя.

#### Scenario: Успешная сборка образа
- **WHEN** выполняется `docker build -t book-shelf .` в корне репозитория
- **THEN** образ собирается без ошибок, а `docker image ls book-shelf` показывает собранный образ

#### Scenario: Dev-зависимости не попадают в образ
- **WHEN** образ собран и выполняется `docker run --rm book-shelf pip list`
- **THEN** в выводе отсутствуют dev-пакеты (`black`, `flake8`, `pytest`, `mypy`) и присутствуют `vk_api`, `requests`, `python-dotenv`

#### Scenario: Процесс работает не от root
- **WHEN** контейнер запущен и выполняется `docker exec book-shelf whoami`
- **THEN** выводится `book-shelf`, а не `root`

### Requirement: Запуск бота в контейнере

Контейнер SHALL запускать бота командой по умолчанию без передачи аргументов. Бот SHALL читать конфигурацию из переменных окружения, включая обязательный `BOT_TOKEN`, `DATA_DIR`, `TEMP_DIR` и `DEBUG`. Логи SHALL попадать в stdout (доступны через `docker logs`).

#### Scenario: Старт с валидным токеном
- **WHEN** контейнер запущен с переменной окружения `BOT_TOKEN`, содержащей валидный токен
- **THEN** процесс остаётся живым, а в логах появляется сообщение о запуске бота и ожидании сообщений

#### Scenario: Отсутствие токена
- **WHEN** контейнер запущен без переменной окружения `BOT_TOKEN`
- **THEN** процесс завершается с ошибкой конфигурации (не запускается с пустым токеном)

### Requirement: Персистентность данных через том

Файл SQLite-базы (`database.db` в каталоге `DATA_DIR`) SHALL сохраняться между пересозданиями контейнера. Compose-конфигурация SHALL монтировать named volume в каталог `DATA_DIR` контейнера.

#### Scenario: Данные переживают пересоздание контейнера
- **WHEN** в работающем контейнере добавлена книга, затем контейнер удалён (`docker compose down`) и запущен заново (`docker compose up -d`)
- **THEN** добавленная книга по-прежнему видна в списке книг бота

#### Scenario: Том не зависит от исходников
- **WHEN** контейнер удалён вместе с образом и пересобран
- **THEN** содержимое named volume (БД) не затрагивается сборкой и остаётся доступным новому контейнеру

### Requirement: Исключение секретов из образа

Сборка SHALL исключать из контекста образов `.env` (с токеном), каталог `data/` (с БД), `logs/`, `temp/`, виртуальное окружение и служебные каталоги через `.dockerignore`.

#### Scenario: Токен не попадает в образ
- **WHEN** в корне репозитория существует `.env` с `BOT_TOKEN`, и выполняется сборка образа
- **THEN** внутри образа отсутствует файл `.env` (например, `docker run --rm book-shelf ls -la /app` не показывает его)

### Requirement: Compose-конфигурация для запуска

В корне репозитория SHALL находиться `docker-compose.yml` с сервисом `book-shelf`, который задаёт сборку из текущего каталога, читает переменные окружения из `.env`, монтирует named volume для данных и использует политику перезапуска `unless-stopped`.

#### Scenario: Запуск одной командой
- **WHEN** в корне репозитория есть `.env` с валидным `BOT_TOKEN`, и выполняется `docker compose up -d`
- **THEN** контейнер собирается (при отсутствии образа) и запускается, бот выходит на связь

#### Scenario: Перезапуск после краха
- **WHEN** процесс бота в контейнере аварийно завершается
- **THEN** Docker перезапускает контейнер согласно политике `restart: unless-stopped`
