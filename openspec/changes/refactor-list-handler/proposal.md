## Why

Текущая реализация команды `/list` размазана по двум файлам: в `list_handler.py` — тонкая обёртка-диспетчер, а вся логика — в `list.py`. Это нарушает принцип единой ответственности и не соответствует стилю остальных обработчиков (хотя `add.py`/`edit.py` тоже используют отдельные файлы, пользователь хочет консолидировать всё в одном месте). Нужно перенести всю реализацию в `list_handler.py`, разбив обработку каждого состояния на отдельные методы класса `ListHandler`, а `list.py` — удалить.

## What Changes

- **Весь код из `list.py`** переносится в `list_handler.py` как методы класса `ListHandler`
- Каждый шаг обработки (`choose_filter`, `choose_status`, `choose_tag`) — отдельный метод `ListHandler`
- `ListHandler.handle()` диспетчеризует по значению `state` из активного стейта
- **`list.py` удаляется**
- **Тесты `tests/handlers/test_list.py`** обновляются: импорты перенаправляются на `list_handler`, вызовы — на методы/через класс
