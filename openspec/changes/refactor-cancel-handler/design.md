## Context

Команда `/cancel` обрабатывается через прямой `if` в `bot.py:126-127`, вызывая функцию `handle_cancel_command` из `cancel.py`. Остальные команды используют `CommandRouter` и `AbstractCommandHandler`. Cancel — единственный обработчик без приоритетной маршрутизации.

## Goals / Non-Goals

**Goals:**
- Создать `CancelHandler` — наследник `AbstractCommandHandler`
- `CancelHandler` должен иметь наивысший приоритет среди всех обработчиков
- Зарегистрировать `CancelHandler` в `CommandRouter`
- Удалить старый файл `cancel.py` и прямой вызов из `bot.py`

**Non-Goals:**
- Изменение логики работы команды `/cancel`
- Изменение сообщений или клавиатуры

## Decisions

1. **Приоритет 100** — выше, чем у всех текущих обработчиков (у всех priority=10). Это гарантирует, что `/cancel` обработается первым, даже если у пользователя активен другой многошаговый сценарий.
2. **Команды `["/cancel", "cancel", "отмена"]`** — сохраняется поддержка и русского слова "отмена", как в старой реализации.
3. **Новый файл `cancel_handler.py`** — по аналогии с другими обработчиками (`add_handler.py`, `edit_handler.py` и т.д.), где класс живёт в `*_handler.py`, а внутренняя логика может быть в `*.py`. Поскольку логика cancel тривиальна, она будет внутри класса, без отдельного файла.

## Risks / Trade-offs

- [Низкий] Если старый `if command == "/cancel"` не удалить полностью, команда может сработать дважды. → Проверить, что `routed is not None` возвращает `True` и цепочка прерывается.
