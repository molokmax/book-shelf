# Specification for daily-reading-goal

## Purpose

Спецификация описывает дневную цель чтения: настройку и просмотр через команду `/goal`, подсчёт прочитанных за день страниц и отображение прогресса цели при обновлении прогресса чтения в VK-боте Book Shelf.

## ADDED Requirements

### Requirement: Хранение дневной цели

Система **SHALL** хранить дневную цель пользователя в таблице `goals` как строку с `kind = "daily_pages"` и положительным целым `target` (страниц в день). Для пары `(user_id, kind)` **SHALL** существовать не более одной строки: повторная установка перезаписывает `target` и `updated_at`. Отключение цели удаляет строку.

#### Scenario: Установка цели

- **WHEN** пользователь без цели устанавливает значение 50
- **THEN** в `goals` появляется строка `kind='daily_pages'`, `target=50` для этого пользователя

#### Scenario: Изменение цели

- **WHEN** пользователь с целью 50 устанавливает значение 30
- **THEN** в `goals` остаётся одна строка с `target=30` и обновлённым `updated_at`

#### Scenario: Отключение цели

- **WHEN** пользователь с целью отключает её
- **THEN** строка цели пользователя удаляется из `goals`

### Requirement: Подсчёт страниц за день

Система **SHALL** считать прочитанные за сегодня страницы как сумму `pages_read` из `read_stats` по `user_id`, где `read_date` не раньше начала текущего календарного дня в локальном времени сервера. Записи с `user_id IS NULL` в сумму не входят.

#### Scenario: Сумма по всем книгам за день

- **WHEN** сегодня в `read_stats` есть записи пользователя на 20 и 15 страниц по разным книгам, плюс запись другого пользователя на 100 страниц
- **THEN** страниц за день для пользователя = 35

#### Scenario: Записи вчерашнего дня не учитываются

- **WHEN** у пользователя есть запись на 10 страниц со вчерашней датой и запись на 5 страниц с сегодняшней
- **THEN** страниц за день = 5

#### Scenario: Записи без user_id не учитываются

- **WHEN** в `read_stats` есть запись на 30 страниц с `user_id IS NULL` и запись пользователя на 5 страниц за сегодня
- **THEN** страниц за день пользователя = 5

### Requirement: Миграция read_stats

При старте системы миграция **SHALL** идемпотентно добавить колонку `user_id` в таблицу `read_stats` (если её ещё нет) и заполнить `user_id` для строк с NULL из `books` по `book_id`. Существующие данные статистики **SHALL** сохраняться.

#### Scenario: Заливка user_id из books

- **WHEN** база создана до миграции: в `read_stats` есть записи книг пользователя, колонки `user_id` нет
- **THEN** после миграции у этих записей проставлен `user_id` владельца книги, остальные данные не изменились

#### Scenario: Повторный запуск миграции

- **WHEN** миграция уже выполнена и система стартует повторно
- **THEN** миграция не изменяет данные и не падает с ошибкой

### Requirement: Команда /goal с меню действий

Система **SHALL** отвечать на команду `/goal` (алиасы `goal`, `цель`) меню с кнопками «Просмотр», «Установить», «Отключить», «Отмена». После любого завершённого действия система **SHALL** отправлять подтверждение с главной клавиатурой и очищать состояние пользователя.

#### Scenario: Вход в меню целей

- **WHEN** пользователь без активного сценария вводит `/goal`
- **THEN** система отправляет сообщение с клавиатурой «Просмотр» / «Установить» / «Отключить» / «Отмена»

#### Scenario: Просмотр цели

- **WHEN** пользователь с целью 50 нажимает «Просмотр», сегодня прочитано 35 страниц
- **THEN** система отправляет сообщение с целью 50, прочитанным за сегодня (35), процентом (70%) и остатком до цели, затем возвращает главную клавиатуру и очищает состояние

#### Scenario: Просмотр без цели

- **WHEN** пользователь без цели нажимает «Просмотр»
- **THEN** система отправляет сообщение «Цель не установлена» с подсказкой установить, возвращает главную клавиатуру и очищает состояние

#### Scenario: Просмотр выполненной цели

- **WHEN** цель 50, сегодня прочитано 60 страниц, пользователь нажимает «Просмотр»
- **THEN** система сообщает, что цель выполнена (не «осталось страниц»)

#### Scenario: Установка цели

- **WHEN** пользователь нажимает «Установить»
- **THEN** система переводит сценарий в состояние ввода числа, просит ввести количество страниц (клавиатура «Отмена»)

#### Scenario: Приём корректного значения

- **WHEN** в состоянии установки пользователь вводит целое число `>= 1`, например 25
- **THEN** система сохраняет цель 25, отправляет подтверждение с главной клавиатурой и очищает состояние

#### Scenario: Значение 0 отключает цель

- **WHEN** в состоянии установки пользователь вводит 0
- **THEN** система отключает цель, отправляет подтверждение отключения с главной клавиатурой и очищает состояние

#### Scenario: Некорректное значение

- **WHEN** в состоянии установки пользователь вводит не целое число или отрицательное значение
- **THEN** система отправляет сообщение об ошибке с подсказкой, сценарий остаётся в состоянии ввода числа

#### Scenario: Отключение цели кнопкой

- **WHEN** пользователь с целью нажимает «Отключить»
- **THEN** система удаляет цель, отправляет подтверждение с главной клавиатурой и очищает состояние

#### Scenario: Отключение без цели

- **WHEN** пользователь без цели нажимает «Отключить»
- **THEN** система отправляет сообщение «Цель не установлена», возвращает главную клавиатуру и очищает состояние

### Requirement: Не перехватывать сценарии других команд

Обработчик `/goal` **SHALL** возвращать `None`, если у пользователя активен сценарий другой команды (`context.is_active()` и `state_info["command"] != "/goal"`), чтобы сообщение обрабатывалось активным сценарием.

#### Scenario: /goal внутри чужого сценария

- **WHEN** пользователь в активном сценарии `/edit` вводит `/goal`
- **THEN** обработчик `/goal` возвращает `None`, сообщение обрабатывается сценарием `/edit`

#### Scenario: Отмена работает глобально

- **WHEN** пользователь в активном сценарии `/goal` вводит «Отмена»
- **THEN** `CancelHandler` сбрасывает состояние `/goal` и выводит сообщение об отмене

### Requirement: Прогресс цели в сообщении обновления прогресса

При успешном завершении обновления прогресса (включая случай «прогресс не изменился»), если у пользователя установлена цель, система **SHALL** добавлять в финальное сообщение строку `Цель на день: X/Y стр.` без эмодзи, где X — прочитано за сегодня, Y — цель. Если цель не установлена, сообщение **SHALL** оставаться без изменений.

#### Scenario: Строка о цели после обновления

- **WHEN** цель 50, после обновления прогресса за сегодня прочитано 35 страниц
- **THEN** финальное сообщение содержит строку `Цель на день: 35/50 стр.`

#### Scenario: Без цели строка не добавляется

- **WHEN** цель не установлена, прогресс обновлён
- **THEN** финальное сообщение не содержит строк о цели

### Requirement: Поздравление при выполнении цели

Система **SHALL** поздравлять пользователя ровно один раз в день — в момент обновления прогресса, при котором сумма страниц за сегодня впервые достигает или превышает цель: дельта обновления положительная и до обновления сумма была меньше цели, а после — не меньше. Вместо обычной строки в финальном сообщении **SHALL** выводиться `🎉 Цель на день выполнена! Сегодня прочитано X из Y страниц.`

#### Scenario: Пересечение порога

- **WHEN** цель 50, за сегодня до обновления 40 страниц, обновление добавляет 15
- **THEN** финальное сообщение содержит поздравление «Цель на день выполнена! Сегодня прочитано 55 из 50 страниц.»

#### Scenario: Повторное обновление после выполнения

- **WHEN** цель уже выполнена сегодня, пользователь обновляет прогресс ещё раз
- **THEN** финальное сообщение содержит обычную строку `Цель на день: X/50 стр.` без поздравления

#### Scenario: Обновление без изменения прогресса не поздравляет

- **WHEN** цель 50, пользователь вводит то же значение прогресса (дельта 0)
- **THEN** сообщение содержит обычную строку о цели без поздравления
