## Context

Обновление прогресса чтения сейчас реализовано внутри `EditHandler`: пользователь проходит выбор фильтра, выбор книги, меню действий и только затем вводит страницу. Это самая частая операция, но путь до неё самый длинный.

Дополнительно в проекте уже есть технический долг:

- диалог выбора книги по статусу, тегам и всем книгам скопирован в `EditHandler`, `DetailsHandler` и `ListHandler`;
- обработка прогресса содержит проверку значения, подтверждение отката и скачка, мини-статистику и автоматическое обновление статуса;
- `CommandRouter` сначала ищет handler по тексту команды и только потом откатывается к handler-у активного состояния.

Задача - добавить короткий вход `/progress`, не меняя доменную логику прогресса и не создавая второй набор правил.

## Goals / Non-Goals

**Goals:**

- Дать команду `/progress` с выбором книги сразу из статуса `reading`.
- Добавить переход `Другие` в стандартный диалог выбора книги.
- Переиспользовать существующую логику проверки, подтверждения, статистики и автостатусов.
- Убрать прогресс из меню действий `/edit`.
- Не перехватывать управление у активного сценария другой команды.
- Вынести переиспользуемые компоненты выбора книги и обновления прогресса.
- Временно сохранить legacy-состояния `/edit`.

**Non-Goals:**

- Менять переходы статусов при обновлении прогресса. Это отдельная задача #67.
- Переводить `list`, `details` и `edit` на общий выбор книги в этом изменении. Это #42.
- Добавлять кнопку `Назад` в многостраничные диалоги. Это #59.
- Решать общую проблему некорректного ввода во всех командах. В рамках этой задачи стандартизируется только `/progress`, общая задача #68.
- Добавлять новые поля книги, статистику или напоминания.

## Decisions

### 1. Отдельный `ProgressHandler`

Новый handler с приоритетом 10 и командами `["/progress", "progress", "прогресс"]` регистрируется в `bot.py` рядом с остальными.

Если у пользователя активен сценарий другой команды, `ProgressHandler.handle` возвращает `None`. Router продолжает поиск, не находит другого handler-а для `/progress` и откатывается к `command_state`, то есть к активному handler-у. Это выполняет требование Q9 без изменения общего router-а.

Альтернатива - менять router и всегда отдавать приоритет активному состоянию. Отклонена: это меняет поведение всех команд и выходит за рамки задачи.

### 2. Список читаемых книг остаётся в handler-е

`ProgressHandler` сам показывает список книг со статусом `reading`, потому что этот экран специфичен для команды: заголовок, кнопка `Другие`, пустое состояние и переход к вводу прогресса.

Для пустого списка handler сразу открывает стандартный диалог фильтров с сообщением, что книг в статусе `«Читаю»` нет. Это экономит одно нажатие.

### 3. `BookSelectionFlow` для стандартного диалога

Новый компонент `src/vk_bot/flows/book_selection.py` инкапсулирует состояния:

- `choose_filter`;
- `selecting_status_filter`;
- `selecting_tag_filter`;
- `selecting_book`.

Компонент получает callback `on_selected(context, book)`, поэтому не знает, что делать с выбранной книгой. Это позволит позже перевести на него `edit`, `details` и `list` в рамках #42.

В этом изменении компонент используется только `ProgressHandler`. Остальные handler-ы не трогаем, чтобы не смешивать функциональную задачу с рефакторингом.

### 4. `ProgressUpdateFlow` для ввода и подтверждения

Новый компонент `src/vk_bot/flows/progress_update.py` содержит:

- показ текущего прогресса и запрос страницы;
- разбор и проверку значения;
- подтверждение отката и скачка;
- применение значения;
- запись статистики;
- мини-статистику;
- завершение сценария.

Компонент используется и новым `ProgressHandler`, и legacy-ветками `EditHandler`. Состояния `waiting_for_progress_input` и `waiting_for_progress_confirm` остаются прежними, поэтому активные сценарии пользователей переживут деплой.

Альтернатива - оставить старую копию в `EditHandler` до удаления legacy. Отклонена: две копии правил быстро разойдутся, а legacy живёт как минимум один релиз.

### 5. Имена состояний

Для нового списка читаемых книг используется `selecting_reading_book`. Остальные состояния стандартного диалога и прогресса сохраняют существующие имена. Это упрощает сравнение с текущим `EditHandler` и делает legacy-делегирование очевидным.

### 6. Стандартное сообщение о неверном вводе

В `utils/helpers.py` добавляется функция:

```python
def format_invalid_input(hint: str) -> str:
    return f"⚠️ Не удалось обработать сообщение. {hint}"
```

Она применяется во всех состояниях `/progress`, где пользователь вводит текст или число. Состояние сохраняется, пользователь может повторить ввод.

Это закрывает часть #68 для нового сценария. Отдельная ветка для текста `/progress` не нужна: команда попадает в текущий шаг как обычный неверный ввод.

### 7. Очистка `/edit`

- Из `_create_book_keyboard` удаляется кнопка `Прогресс`.
- Из `_handle_selecting_action` удаляется ветка `прогресс`.
- В конец `_handle_selecting_action` добавляется общий fallback: `⚠️ Выбери действие` и клавиатура действий.
- Состояния `waiting_for_progress_input` и `waiting_for_progress_confirm` делегируют в `ProgressUpdateFlow`.
- На legacy-делегирование ставится `TODO(#69)`.

### 8. Главная клавиатура и документация

Раскладка:

```
/progress  /edit     /add
/list      /details  /export
/stats     /help
```

Тексты `/start` и `/help` дополняются описанием `/progress`. README получает строку о новой команде.

### 9. Тесты

- Новый `tests/handlers/test_progress_handler.py` покрывает вход, список `reading`, пустой список, `Другие`, стандартные фильтры и выбор книги.
- Тесты прогресса переносятся из `test_edit_handler.py` в тесты `ProgressUpdateFlow` и нового handler-а.
- Отдельно проверяется, что `ProgressHandler` возвращает `None` при активном чужом состоянии.
- Отдельно проверяется, что legacy-состояния `/edit` продолжают работать через `ProgressUpdateFlow`.
- Проверяется fallback в меню действий `/edit`.

## Risks / Trade-offs

- **Risk:** `ProgressHandler` возвращает `None`, и router может не найти fallback, если состояние повреждено.
  **Mitigation:** тест на маршрутизацию с активным `/edit` и защита от пустого `command_state`.

- **Risk:** Перенос прогресса из `EditHandler` ломает существующие тесты, которые патчат `eh.BookService` и `eh.ReadingStatsService`.
  **Mitigation:** тесты переносятся вместе с логикой и патчат модули новых компонентов.

- **Risk:** Пользователь с активным `/progress` после отката версии останется без handler-а.
  **Mitigation:** откат выполняется вместе с отключением новой команды, пользователь может нажать `/cancel` или `/start`. Legacy-состояния `/edit` при этом продолжают работать.

- **Risk:** Текст `/progress` в активном `/add` станет названием книги.
  **Mitigation:** это осознанное решение Q13. Отдельная защита текстовых полей от команд не входит в задачу.

- **Risk:** `BookSelectionFlow` и legacy-диалоги временно сосуществуют.
  **Mitigation:** это зафиксировано в #42. Новый компонент не меняет поведение старых handler-ов.

## Migration Plan

1. Задеплоить новый handler и компоненты.
2. Активные состояния `/edit` с прогрессом продолжают работать через делегирование.
3. Пользователи начинают использовать `/progress`.
4. После переходного периода удалить legacy-делегирование по #69.
5. Мигрировать остальные диалоги выбора книги по #42.

## Open Questions

Нет. Спорные переходы статусов остаются в #67 и в этом изменении не меняются.
