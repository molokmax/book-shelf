## Context

После применения прогресса `ProgressUpdateFlow._finish_progress_update` (`src/vk_bot/flows/progress_update.py:145-161`) отправляет сообщение из блоков: заголовок, мини-статистика, опциональная строка цели дня. Блоки склеиваются `"\n\n"`. Единственный поощрительный элемент: строка «🎉 Цель на день выполнена!», срабатывает только в момент выполнения цели.

Настройки хранятся в типизированной таблице `user_settings` (одна строка на пользователя, колонка на настройку). Экран `/settings` (`src/vk_bot/handlers/settings.py`) показывает период скорости чтения, кнопки текстовые, матчинг по `context.text.strip().lower()`. Тогглов в кодовой базе нет.

Схема создаётся идемпотентно: `CREATE TABLE IF NOT EXISTS` в `Database._create_tables` (`src/core/database.py:60-178`) и миграции-функции в `src/core/migrations.py`, вызываемые из `Database.__init__` при каждом старте. Прецедент сида строк: `resolve_or_create_tags`.

Ключевые решения зафиксированы в grilling-сессии по issue #47 (см. ниже), альтернативы перечислены у каждого решения.

## Goals / Non-Goals

**Goals:**

- После успешного обновления прогресса подбадривать пользователя случайной мотивационной фразой из таблицы `motivational_phrases`.
- Начальный список из 15 фраз добавлять идемпотентной миграцией; пополнять списка новыми миграциями.
- Схема таблицы сразу готова к сценарному подбору (категория фразы), при этом выбор в v1 игнорирует категорию.
- Настройка «Мотивация» (вкл/выкл, по умолчанию вкл) на экране `/settings`.
- Формулировки сид-фраз универсальны: уместны при росте, откате и завершении книги.

**Non-Goals:**

- Сценарный подбор по категории (тренд страниц, цель достигнута): колонка создаётся сейчас, выбор добавится позже.
- Анти-повтор (фраза не та же, что в прошлый раз): чистый random, словарь last-фразы не храним.
- Пер-пользовательские или редактируемые в боте фразы: глобальный список, пополняется миграциями.
- Показ фразы при обновлении прогресса через `/edit`: только сценарий `/progress`.
- Исправление устаревших описаний AGENTS.md / README (док-дрифт вне скоупа).

## Decisions

1. **Каноничная терминология**: «мотивационная фраза» (запись), фича «мотивация». Имена: `MotivationPhrase`, таблица `motivational_phrases`, настройка `motivation_enabled`. Альтернативы из issue: «поощряющее сообщение», «подбадривающая фраза» отвергнуты как синонимы, нужен один термин для кода и глоссария.

2. **Схема таблицы**:

   ```sql
   CREATE TABLE IF NOT EXISTS motivational_phrases (
       id TEXT PRIMARY KEY,                -- uuid, конвенция tags/books
       text TEXT NOT NULL UNIQUE,          -- основа идемпотентности сида
       category TEXT NOT NULL DEFAULT 'general'
           CHECK (category IN ('general', 'trend_up', 'trend_down', 'goal_reached')),
       created_at TEXT NOT NULL DEFAULT (datetime('now'))
   )
   ```

   `TEXT` uuid PK по конвенции репозитория (tags, books, goals). `UNIQUE(text)` делает сид честно идемпотентным при любых правках списка (`INSERT OR IGNORE`), альтернатива «сравнение с количеством» хрупка. `CHECK` согласован с существующим `CHECK (reading_speed_period_days IN (7, 14, 30))`; репозиторий разворачивает константы категорий из `core.models` (`PhraseCategory`). `created_at` с SQLite-значением по умолчанию: фразы создаются только миграциями.

3. **Сид**: функция `seed_motivational_phrases(conn)` в `src/core/migrations.py` по образцу `resolve_or_create_tags`, вызывается из `Database.__init__` рядом с остальными миграциями. `INSERT OR IGNORE` всех 15 фраз со статусом `general`. Отключение элемента списка не удаляет его: правки списка делаются новыми миграциями.

4. **Выбор в v1 и шов под сценарии**: `MotivationPhraseRepository.get_random_phrase() -> str | None`: `SELECT text FROM motivational_phrases ORDER BY RANDOM() LIMIT 1`, `None` при пустой таблице (не ошибка). Логика выбора в `MotivationService.pick_phrase(context: MotivationContext)`. `MotivationContext` (dataclass в `core/models.py`): `previous_page`, `new_page`, `pages_delta`, `finished` (книга завершена), `goal_completed`. В v1 контекст формируется, но игнорируется: сценарные стратегии (goal_reached, trend) заменят стратегию без правок флоу. Проверка категории при `SELECT` не выполняется. Альтернатива «хендлер тянет случайную фразу из репозитория напрямую» отвергнута: заменяет стратегию переписыванием флоу, а не одной функции.

5. **Встраивание во флоу**: в `_finish_progress_update` после сборки `parts`. Правила показа: фраза только когда прогресс изменился (при `unchanged` не добавляется) и когда в сообщении нет строки «🎉 Цель на день выполнена!» (поздравление уже выполняет мотивационную роль, два блока подряд перебор). Блоки с обычной строкой цели («Цель на день: X/Y стр.») фразу не исключают. Проверка включённости (п. 6) до вызова сервиса. Фраза добавляется последним блоком `parts`. Сбои выбора обрабатываются как в `_format_goal_progress`: ошибка сервиса не ломает подтверждение прогресса.

6. **Хранение тоггла**: колонка `motivation_enabled INTEGER NOT NULL DEFAULT 1` в `user_settings` по зафиксированному принципу change `add-user-settings` («каждая новая настройка это колонка + пункт экрана»; key-value и JSON в `user_state` там отвергнуты). Отсутствие строки = включена, что даёт дефолт «вкл» бесплатно. Репозиторий: `get_motivation_enabled(user_id) -> bool` и upsert-версия сохранения настроек. Сервис: `UserSettingsService.is_motivation_enabled(...)` / `set_motivation_enabled(...)` с валидацией типов.

7. **Миграция для существующих БД**: `CREATE TABLE IF NOT EXISTS` не добавит колонку в уже созданные `user_settings`, поэтому миграция `add_user_settings_motivation_column(conn)` по образцу `add_read_stats_user_id`: проверка `PRAGMA table_info(user_settings)`, затем `ALTER TABLE user_settings ADD COLUMN motivation_enabled INTEGER NOT NULL DEFAULT 1`. Идемпотентна, вызывается из `Database.__init__`.

8. **Экран настроек**: в текст добавляется строка «Мотивация: включена/выключена». Одна кнопка-переключатель с динамической меткой «Мотивация: Вкл» / «Мотивация: Выкл», цвет `VkKeyboardColor.PRIMARY` когда вкл, `SECONDARY` когда выкл (раскраска по образцу `tag_editing_keyboard`). Тап инвертирует состояние, бот отвечает «Мотивация включена/выключена» той же клавиатурой, сценарий остаётся активен (прецедент периода). Раскладка: ряд 1 «7 дней», «14 дней»; ряд 2 «30 дней», «Мотивация: Вкл/Выкл»; ряд 3 «Назад». `goal.py`-стиль из двух кнопок («Включить»/«Отключить») отвергнут: состояние видно в одном месте, переключение одним тапом.

9. **Список 15 фраз (сид v1)**: эмодзи хранится в тексте фразы (каждая фраза со своим), обращение на «ты», формулировки универсальны:

   1. `💪 Отличный прогресс!`
   2. `📚 Каждая страница это шаг вперёд.`
   3. `✨ Ты читаешь регулярно, и это здорово!`
   4. `🔥 Прогресс налицо!`
   5. `🌱 Маленькие шаги складываются в прочитанные книги.`
   6. `🧠 Прочитанное остаётся с тобой.`
   7. `🏆 Ты на верном пути!`
   8. `😊 Есть чем гордиться!`
   9. `🚀 Скорость не главное, главное постоянство.`
   10. `📖 Чтение это инвестиция в себя.`
   11. `⭐ Отличная привычка, продолжай!`
   12. `💫 Знания из книги уже работают на тебя.`
   13. `🌟 Так держать!`
   14. `🎯 Регулярность важнее объёма.`
   15. `❤️ Хорошая книга в хороших руках.`

10. **Покрытие тестами**: флоу-тесты на стабах (фраза добавлена при включённой настройке; нет при выключенной, при `unchanged` и при выполненной цели; механика стабов по образцу `tests/flows/test_progress_update.py`), тест хендлера настроек (переключение, метки, раскраска), тест миграций (идемпотентность сида, добавление колонки на старой БД), сервисный тест на sqlite в `tmp_path` по образцу `tests/test_user_settings_service.py` (выбор фразы, `None` на пустой таблице, тоггл).

## Risks / Trade-offs

- [Чистый random даёт повторы при частых обновлениях, при 15 фразах уже за несколько дней] → Обсуждено и принято (issue #47): анти-повтор добавляется позже одной строкой; сценарный подбор решит проблему выбором по контексту.
- [`ORDER BY RANDOM()` сканирует таблицу] → Для открытого списка в десятки строк стоимость несущественна; при заметном росте лимита/частоты подмены на `random.choice` из отфильтрованного набора.
- [Общая тон фразы может промахнуться по контексту, например завершение книги] → Принято решение Q8: сид формулируется универсально; сценарные категории ликвидируют промах потом.
- [Сид выполняется при каждом старте] → `INSERT OR IGNORE` по `UNIQUE(text)` идемпотентен и дёшев (15 строк).
- [Миграция колонки в `user_settings` на существующих БД] → Проверка через `PRAGMA table_info` + `ALTER TABLE ADD COLUMN`, идемпотентность тестируется.

## Migration Plan

1. Схема: `motivational_phrases` создаётся в `_create_tables`; `motivation_enabled` добавляется миграцией для существующих БД.
2. Данные: сид 15 фраз при первом старте; повторные старты ничего не меняют.
3. Откат: колонка и таблица после миграции остаются (безобидные при старом коде); код старой версии игнорирует новые колонку/таблицу. Отдельного даун-миграционного шага нет по принятым конвенциям (идемпотентные миграции при каждом старте).
