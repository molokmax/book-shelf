## ADDED Requirements

### Requirement: Персональный справочник тегов

Система **SHALL** хранить теги в персональном справочнике: набор тегов у каждого пользователя свой, имена уникальны в рамках пользователя без учёта регистра. Справочник **SHALL** пополняться только в момент сохранения книги с тегом, которого нет в справочнике пользователя.

#### Scenario: Новый тег попадает в справочник при сохранении книги

- **WHEN** пользователь подтверждает шаг выбора тегов с тегом, которого нет в его справочнике
- **THEN** тег создаётся в справочнике пользователя и привязывается к книге

#### Scenario: Наборы тегов разных пользователей независимы

- **WHEN** два пользователя сохраняют книги с тегом «Классика»
- **THEN** у каждого пользователя в справочнике своя запись тега, наборы не пересекаются

#### Scenario: Регистр не создаёт дубликаты

- **WHEN** пользователь вводит «tech», а в его справочнике есть «Tech»
- **THEN** используется существующий тег «Tech», новая запись не создаётся

### Requirement: Привязка тегов к книге

Теги книги **SHALL** храниться через привязки к записям справочника. Отображаемые теги книги **SHALL** сортироваться по алфавиту без учёта регистра. Книга **MAY** не иметь тегов.

#### Scenario: Чтение книги возвращает теги из привязок

- **WHEN** пользователь открывает список, детали или экспорт книги с тегами
- **THEN** теги книги соответствуют текущим привязкам

#### Scenario: Удаление книги не удаляет теги из справочника

- **WHEN** пользователь удаляет книгу с тегами
- **THEN** привязки тегов удаляются вместе с книгой, записи справочника остаются

### Requirement: Шаг выбора тегов

Команды добавления и редактирования книги **SHALL** использовать шаг выбора тегов: кнопки-переключатели тегов из справочника, ввод новых тегов списком через запятую, завершение кнопкой «Готово». Шаг **SHALL NOT** завершаться до подтверждения пользователем.

#### Scenario: Предвыбор текущих тегов при редактировании

- **WHEN** пользователь доходит до шага тегов в `/edit`
- **THEN** текущие теги книги показаны выбранными

#### Scenario: Переключение тега кнопкой

- **WHEN** пользователь нажимает кнопку тега
- **THEN** тег добавляется в выборку или убирается из неё, шаг продолжается, бот показывает актуальную выборку

#### Scenario: Ввод новых тегов текстом

- **WHEN** пользователь вводит «Классика, Русская литература»
- **THEN** оба тега добавляются к выборке, шаг продолжается

#### Scenario: Подтверждение текстом

- **WHEN** пользователь отправляет текст «готово»
- **THEN** шаг завершается как при нажатии кнопки «Готово»

#### Scenario: Пустая выборка при добавлении

- **WHEN** пользователь в `/add` нажимает «Готово» с пустой выборкой
- **THEN** книга создаётся без тегов

#### Scenario: Пустая выборка при редактировании

- **WHEN** пользователь в `/edit` снимает все теги и нажимает «Готово»
- **THEN** у книги не остаётся тегов, подтверждение не запрашивается

### Requirement: Клавиатура шага выбора

Клавиатура шага **SHALL** показывать теги справочника по два в ряд, не более 16 тегов на страницу, выбранные теги подсвечены. Клавиатура **SHALL** содержать ряд «Готово» и «Отмена» и пагинацию, если теги не помещаются на одну страницу.

#### Scenario: Подсветка выбранных тегов

- **WHEN** шаг отображается с непустой выборкой
- **THEN** выбранные теги визуально отличаются от невыбранных

#### Scenario: Пагинация справочника

- **WHEN** справочник пользователя содержит больше 16 тегов
- **THEN** клавиатура содержит кнопки перехода между страницами тегов

### Requirement: Маршрутизация кнопок шага

Кнопки тегов и «Готово» **SHALL** нести payload с командой владельца активного сценария. Тег из payload **SHALL** валидироваться по справочнику пользователя.

#### Scenario: Имя тега совпадает с командой

- **WHEN** пользователь нажимает кнопку тега с именем «/add» или «Отмена» в шаге выбора тегов
- **THEN** сообщение обрабатывается шагом выбора тегов владельца, а не перехватывается другими обработчиками

#### Scenario: Подменённый payload

- **WHEN** приходит payload с тегом, которого нет в справочнике пользователя
- **THEN** бот отвечает сообщением о некорректном вводе, шаг продолжается

### Requirement: Фильтр по тегам

Фильтр «По тегам» **SHALL** строиться только по тегам, привязанным хотя бы к одной книге пользователя.

#### Scenario: Неиспользуемый тег не попадает в фильтр

- **WHEN** в справочнике пользователя есть тег, не привязанный ни к одной книге
- **THEN** этого тега нет в клавиатуре фильтра «По тегам»

### Requirement: Перенос существующих тегов

При первом запуске новой версии существующие теги книг **SHALL** переноситься в справочник и привязки, колонка `books.tags` **SHALL** удаляться. Повторные запуски **SHALL** быть без изменений.

#### Scenario: Первый запуск с существующими данными

- **WHEN** база содержит книги с заполненной колонкой `books.tags`
- **THEN** после запуска теги лежат в справочнике и привязках, колонка `books.tags` отсутствует
