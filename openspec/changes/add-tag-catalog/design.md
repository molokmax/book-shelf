## Context

Теги хранятся в колонке `books.tags` (TEXT) как Python-repr списка: запись `str(book.tags)`, чтение `eval()` (`src/core/database.py`, `add_or_update_book` и все геттеры). Справочника тегов нет: `BookService.get_all_tags(user_id)` агрегирует теги из книг пользователя. Ввод тегов: `/add` ручной (`waiting_for_tags`) и LitRes (`waiting_for_litres_tags`), строка через запятую, пустой ввод = без тегов; `/edit`: `editing_tags`, последний шаг, «Дальше» = оставить, текст = полная замена. Фильтр «По тегам» (`list.py`, `edit.py`, `flows/book_selection.py`) строит клавиатуру `tags_keyboard(tags)` текстовыми кнопками без payload.

Роутер: первый проход по `context.command` (payload `command` или текст кнопки), второй по команде активного состояния. `CancelHandler` (priority 100) перехватывает «отмена»/«cancel»/«/cancel» первым проходом. VK-клавиатура чата: до 40 кнопок, до 10 рядов по 5 (inline до 10, не подходит). `get_db`: глобальный синглтон, все сервисы делят подключение. Миграции: идемпотентные функции в `core/migrations.py`, вызов из `Database.__init__`. SQLite: локально 3.45.3, контейнер `python:3.11-slim` (SQLite 3.40.x), `DROP COLUMN` доступен (3.35+). Термин разъезжается: `add.py` «теги», `edit.py` «тэги», CONTEXT.md «теги», определения в глоссарии нет.

## Goals / Non-Goals

**Goals:**

- Персональный справочник тегов: набор тегов у каждого пользователя свой
- Привязка тегов к книге через many-to-many, одна правда о тегах книги
- Интерактивный шаг выбора тегов в `/add` (ручной и LitRes) и `/edit`: кнопки-переключатели из справочника, ввод новых через запятую, завершение только по «Готово»
- Перенос существующих тегов книг в новую структуру, колонка `books.tags` удаляется
- Канонический термин «тег» в сообщениях и глоссарии

**Non-Goals:**

- Переименование, удаление и слияние тегов справочника: схема готова к этим операциям, сами операции отдельными change
- Payload для тег-кнопок фильтров «По тегам»: issue #83
- Лимиты на количество тегов книги и длину имени тега
- Управление порядком тегов книги: порядок фиксированно алфавитный

## Decisions

1. **Полная нормализация: `tags` + `book_tags`, колонка `books.tags` удаляется**
   ```sql
   CREATE TABLE IF NOT EXISTS tags (
       id TEXT PRIMARY KEY,
       user_id TEXT NOT NULL,
       name TEXT NOT NULL,
       created_at TEXT NOT NULL,
       UNIQUE(user_id, name),
       FOREIGN KEY (user_id) REFERENCES users (id)
   );

   CREATE TABLE IF NOT EXISTS book_tags (
       book_id TEXT NOT NULL,
       tag_id TEXT NOT NULL,
       PRIMARY KEY (book_id, tag_id),
       FOREIGN KEY (book_id) REFERENCES books (id) ON DELETE CASCADE,
       FOREIGN KEY (tag_id) REFERENCES tags (id) ON DELETE CASCADE
   )
   ```
   - Альтернатива: справочник + JSON в `books.tags`. Отвергнута: две правды, риск рассинхрона, `eval()` остаётся.
   - `Book.tags: list[str]` остаётся публичным API модели: хендлеры, форматтеры и экспорт CSV не переписываются.

2. **Нормализация имён тегов** (см. `utils.helpers.normalize_tag_name`): trim, схлопывание внутренних пробелов, непустая проверка. Уникальность в рамках пользователя регистронезависимо: сравнение `str.casefold()` на стороне приложения (SQLite `COLLATE NOCASE` фолдит только ASCII). Отображаемое имя: первая введённая форма; ввод «tech» при существующем «Tech» резолвится в «Tech».

3. **Порядок тегов книги: алфавит, без колонки `position`**: гидратация сортирует по `str.casefold()` в Python. Альтернатива с сохранением порядка выбора отвергнута: алфавит стабилен для отображения и экспорта.

4. **Запись инкапсулирована в `Database.add_or_update_book`, один курсор**: upsert строки книги, ensure недостающих тегов справочника (casefold-резолв), `DELETE FROM book_tags WHERE book_id = ?`, INSERT привязок, один commit. Справочник пополняется только в момент сохранения книги, отмена сценария не оставляет следов. Явные DELETE+INSERT вместо опоры на каскады `INSERT OR REPLACE`.

5. **Чтение: `TagRepository` + `TagService`, фильтры на тегах в использовании**: `TagRepository` (`get_user_tags` справочник, `get_used_tags` привязанные) в `core/repository.py`, тонкий `TagService` поверх для flows. `BookService.get_all_tags` переподключается на `get_used_tags`, сигнатура и семантика не меняются. Гидратация тегов книги во всех геттерах `Database`.

6. **Механика шага `selecting_tags`**:
   - Вход: текущая выборка (в `/edit` предвыбраны текущие теги книги, в `/add` пусто), клавиатура тегов + «Готово» + «Отмена».
   - Клик по тегу: toggle, шаг продолжается, новое сообщение с актуальной выборкой и клавиатурой.
   - Текст: «готово» (casefold) завершает шаг; иначе split по запятым, имена добавляются к выборке (casefold-резолв к каноническим именам), шаг продолжается; пустой результат split: `format_invalid_input`, шаг продолжается.
   - «Готово»: `/add` создаёт книгу (пустая выборка = без тегов), `/edit` применяет накопленные поля + теги (пустая выборка = снять все теги, без дополнительного подтверждения).
   - Финальные сообщения перечисляют итоговые теги («Теги: A, B» или «Теги: нет»).
   - Тег с именем «Готово» недостижим одиночным текстовым вводом; ввести его можно только в составе списка с другими тегами. Компромисс осознанный.

7. **Клавиатура шага**: 2 тега в ряд, 16 тегов на страницу (8 рядов), ряд «Готово» (positive) + «Отмена» (negative), ряд «Ещё →» / «← Назад» при числе страниц больше одной. Выбранные теги primary, невыбранные secondary. Не больше 10 рядов и 20 кнопок: лимит VK (40 кнопок, 10 рядов) соблюдён. Номер страницы в `data` состояния, границы клампятся при рендере.

8. **Payload-роутинг кнопок шага**: тег-кнопка `{"command": "<владелец>", "action": "toggle", "tag": "<имя>"}`, «Готово» `{"command": "<владелец>", "action": "done"}`, пагинация `{"command": "<владелец>", "action": "prev_page" | "next_page"}`, «Отмена» `{"command": "/cancel"}` как везде. Первый проход роутера приводит сообщение владельцу состояния независимо от текста кнопки: имена тегов («/add», «edit», «отмена», «готово») ничему не конфликтуют. Тег из payload валидируется по справочнику: подменённый payload получает `format_invalid_input`, шаг продолжается.

9. **`TagEditingFlow` как компонент без собственной команды**: `src/vk_bot/flows/tag_editing.py` по образцу `BookSelectionFlow`: `start(context, state_info, preselected)` и `handle(context, state_info)`, колбэк `on_done(context, tags)`. Состояние `selecting_tags` живёт внутри команды владельца: `/add` хранит `origin` (manual/litres) и данные книги, `/edit` хранит `selected_book_id` и накопленные `new_*`. Гарды и `CancelHandler` работают как раньше. `user_id` для чтения справочника: паттерн `_get_user_id` из `BookSelectionFlow`.

10. **Миграция данных** `migrate_books_tags(conn)` в `core/migrations.py`, вызов из `Database.__init__` после `_create_tables`:
    - нет колонки `tags` в `books`: ранний возврат (идемпотентность);
    - для каждой книги с непустым значением: парсинг `ast.literal_eval`, fallback `json.loads`, при неудаче пустой список и warning в лог;
    - casefold-дедуп по каждому пользователю, первое имя каноническое;
    - `INSERT OR IGNORE` в `tags`, пересборка `book_tags` книги (DELETE + INSERT);
    - `ALTER TABLE books DROP COLUMN tags` в try/except `OperationalError`;
    - колонка `tags` убирается из `CREATE TABLE books` и `_book_column_list`.
    Альтернатива «заморозить колонку» отвергнута: схема остаётся честной, свежие и мигрированные базы сходятся к одной схеме.

11. **Терминология**: канонический термин «тег», унификация сообщений (`edit.py` строки 495 и 499, `services.py` докстринг 162), термины «Тег» и «Набор тегов пользователя» в `CONTEXT.md`. Идентификаторы кода (`tags`, `book_tags`) не меняются.

## Risks / Trade-offs

- **[Потеря тегов при повреждённом repr]**: если `books.tags` не парсится ни как Python-repr, ни как JSON, книга остаётся без тегов, warning в лог. Значение невосстановимо, честнее пустого списка с предупреждением.
- **[DROP COLUMN и старый SQLite]**: нужен 3.35+ (локально 3.45.3, контейнер 3.40.x). На старой библиотеке колонка не удаляется, но остаётся мёртвой: код её не читает и не пишет.
- **[Откат требует бэкапа]**: старый код не читает новую схему (колонки `books.tags` нет). Перед первым запуском копия `data/database.db`; откат = старый код + бэкап. Зафиксировать в README.
- **[Сообщение на каждое действие]**: каждый toggle и ввод отправляет сообщение с клавиатурой. Паттерн уже используется (меню `/settings`).
- **[Тег «Готово»]**: недостижим одиночным вводом, осознанный компромисс.
- **[Устаревшая страница в состоянии]**: границы страницы клампятся при рендере, состояние одно на пользователя.

## Migration Plan

1. `_create_tables`: таблицы `tags`, `book_tags` со схемой из решения 1.
2. `migrate_books_tags` из решения 10, вызов после `_create_tables` и существующих миграций.
3. `CREATE TABLE books` и `_book_column_list` без `tags`; `add_or_update_book` и геттеры переключаются на `book_tags`.
4. Идемпотентность: повторные запуски ничего не меняют.
5. Перед первым запуском: копия `data/database.db` (раздел об обновлении в README).
