## Context

Команда `/details` реализована в двух файлах: `details.py` (логика) и `details_handler.py` (тонкая обёртка). Каждый шаг многошагового состояния обрабатывается в одной большой функции `handle_details_step` с цепочкой `if/elif`. Такой код сложно поддерживать, тестировать отдельные шаги и расширять.

Аналогичные обработчики (`AddHandler`, `EditHandler`) следуют тому же паттерну «два файла», но данная задача — пилотный рефакторинг, после которого будет принято решение о рефакторинге остальных.

## Goals / Non-Goals

**Goals:**
- Вся логика команды `/details` находится внутри `DetailsHandler` в `details_handler.py`
- Каждое состояние обрабатывается отдельным приватным методом
- Диспетчеризация по `state` из активного стейта в методе `handle`
- `details.py` удалён
- Тесты обновлены под новую структуру

**Non-Goals:**
- Изменение поведения команды `/details` для пользователя
- Рефакторинг других обработчиков (`add`, `edit` и т.д.)
- Изменение схемы данных стейта или формата ответов

## Decisions

| Decision | Rationale |
|----------|-----------|
| Приватные методы `_handle_<state>` вместо отдельных функций | Единая инкапсуляция в классе; методы имеют доступ к `self`, если понадобится общее состояние |
| Метод `handle` диспетчеризует по `context.get_state()["state"]` | Прямое отображение стейта на метод; легко добавлять новые шаги |
| `handle_details_step` не сохраняется — каждый шаг становится отдельным методом | Устраняет громоздкий `if/elif`, упрощает тестирование каждого шага изолированно |
| `handle_details` переезжает как `_handle_entry` | Чистый entry-point, вызываемый, когда нет активного `/details`-стейта |

**Альтернативы, которые рассматривались:**
- Оставить `details.py` как модуль с функциями, но разбить их — не решает проблему двух файлов
- Вынести функции шагов в отдельный модуль `details_steps.py` — ещё больше файлов без выгоды

## Risks / Trade-offs

| Риск | Митигация |
|------|-----------|
| Сломанная диспетчеризация: неправильное чтение `state` из стейта | Тесты покрывают все состояния; проверка `context.is_active()` и `state_info.get("command")` остаётся |
| Забытый импорт `details` где-то ещё (в `__init__.py` или тестах) | Полный grep по проекту после удаления файла |
| Тесты импортируют `handle_details` / `handle_details_step` из `details.py` | Все тесты обновляются в рамках этого изменения; CI-прогон подтверждает |
