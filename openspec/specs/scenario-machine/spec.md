# Specification for scenario-machine

## Purpose

Спецификация описывает жизненный цикл многошаговой команды VK-бота Book Shelf: владение сценарием при активном диалоге, вход, обработку шагов, переходы, завершение, повторный ввод команды и поведение при неизвестном состоянии.

## Requirements

### Requirement: Владение сценарием

При активном сценарии команды X обработчик любой другой несистемной команды **SHALL** ответить отказом «⚠️ Сейчас активна другая операция. Заверши её или нажми «Отмена».» и **SHALL NOT** изменять состояние сценария X. Системные команды `/start` и `/cancel` **SHALL** выполняться всегда; `/start` **SHALL** отправлять приветствие перед удалением активного состояния.

#### Scenario: Несистемная команда внутри чужого сценария

- **WHEN** у пользователя активен сценарий `/add` на шаге ввода названия, и он отправляет `/help`
- **THEN** бот отвечает текстом отказа, состояние `/add` и его данные не меняются

#### Scenario: «Ещё» и «Назад» внутри чужого сценария

- **WHEN** у пользователя активен сценарий `/edit`, и он нажимает кнопку «Ещё» на устаревшей клавиатуре
- **THEN** бот отвечает текстом отказа, сценарий `/edit` продолжается со своего текущего шага

#### Scenario: Отмена работает глобально

- **WHEN** в активном сценарии пользователь отправляет «Отмена»
- **THEN** `CancelHandler` сбрасывает состояние и отправляет «Операция отменена» с главной клавиатурой

#### Scenario: /start сбрасывает сценарий

- **WHEN** в активном сценарии `/add` пользователь отправляет `/start`
- **THEN** бот отправляет приветствие с главной клавиатурой, затем состояние удаляется

### Requirement: Вход в сценарий

Команда без активного состояния **SHALL** создавать состояние `{"command", "state", "data"}` с начальным шагом сценария и отправлять промпт начального шага.

#### Scenario: Первый запуск команды

- **WHEN** пользователь без активного сценария отправляет `/goal`
- **THEN** создаётся состояние с `command = "/goal"` и начальным шагом меню, бот отправляет экран выбора действия

### Requirement: Обработка шага и переходы

Каждое следующее сообщение активного сценария **SHALL** обрабатываться шагом текущего состояния. Шаг, не выполнивший переход, **SHALL** оставлять пользователя в том же шаге. Переход **SHALL** сохранять новое состояние до отправки промпта нового шага.

#### Scenario: Ошибка валидации остаётся в шаге

- **WHEN** на шаге ввода количества страниц пользователь отправляет «abc»
- **THEN** бот отправляет сообщение об ошибке и остаётся на том же шаге; накопленные данные не меняются

#### Scenario: Успешный переход

- **WHEN** на шаге ввода названия пользователь отправляет «Мастер и Маргарита»
- **THEN** название сохраняется в данных, состояние переходит к шагу автора, бот отправляет промпт автора

### Requirement: Завершение сценария

Финал **SHALL** отправлять финальное сообщение до удаления состояния; после финала активного состояния у пользователя нет. Финальное сообщение **SHALL** оставаться в истории чата.

#### Scenario: Успешный финал

- **WHEN** пользователь подтверждает выборку тегов при добавлении книги
- **THEN** книга создаётся, бот отправляет результат с главной клавиатурой, состояние удаляется

### Requirement: Повторный ввод команды сценария

Если активен сценарий команды и пользователь вводит эту же команду явно (payload-команда или текст, начинающийся с `/`), сценарий **SHALL** перезапуститься с начального шага, а накопленные данные **SHALL** быть отброшены. Алиасы без слэша перезапуском не считаются и обрабатываются как ввод шага.

#### Scenario: Повторный /add

- **WHEN** на шаге ввода названия книги пользователь отправляет `/add`
- **THEN** состояние создаётся заново с начального шага выбора способа; «/add» не становится названием книги

### Requirement: Неизвестное состояние

Если активное состояние принадлежит сценарию, но его шаг отсутствует в перечислении шагов, сценарий **SHALL** сбросить состояние: отправить финальное сообщение «⚠️ Не удалось продолжить сценарий. Начни заново: <команда>» с главной клавиатурой и удалить состояние. Обработка **SHALL NOT** завершаться необработанным исключением.

#### Scenario: Неизвестный шаг

- **WHEN** в состоянии пользователя сохранён шаг, которого нет в перечислении шагов сценария
- **THEN** бот отправляет сообщение о сбросе с главной клавиатурой и удаляет состояние

### Requirement: Формат состояния и имена шагов

Формат состояния **SHALL** содержать `{"command": str, "state": str, "data": dict}` и **MAY** содержать дополнительное поле `history` для навигации «Назад». Имена шагов **SHALL** задаваться перечислениями `StrEnum` и совпадать со строками, сохранёнными у существующих пользователей. Общие шаги под-сценариев **SHALL** иметь одинаковые значения во всех сценариях, которые их используют.

#### Scenario: Совместимость с сохранённым состоянием

- **WHEN** после обновления у пользователя в `user_state` сохранён шаг `waiting_for_title` с `command = "/add"`
- **THEN** сценарий продолжается с шага ввода названия, а после отправки названия переходит к шагу ввода автора без миграции данных

### Requirement: Общие шаги под-сценариев

Шаги выбора тегов, выбора книги и обновления прогресса **SHALL** сохранять `command` сценария-владельца. По завершении шаг **SHALL** либо возвращать управление этому сценарию (теги, выбор книги), либо завершать сценарий финальным сообщением (обновление прогресса).

#### Scenario: Теги внутри /add и /edit

- **WHEN** пользователь проходит шаг выбора тегов в `/add` или `/edit`
- **THEN** `command` состояния остаётся `/add` или `/edit` соответственно, а после подтверждения вызывается финал соответствующего сценария

#### Scenario: Обновление прогресса внутри /progress

- **WHEN** пользователь подтверждает значение прогресса в `/progress`
- **THEN** `command` состояния остаётся `/progress`, бот отправляет результат и удаляет состояние
